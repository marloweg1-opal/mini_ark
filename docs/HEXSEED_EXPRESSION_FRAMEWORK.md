# HEXSEED Expression Framework

## Canonical Short Form

HEXSEED is the persistent platform.

Journey configures it.

Functional kernels define what work exists.

Expression profiles define how that work is understood and presented.

CareBloomOS is the first mature profile, not the base ontology.

All expression profiles are peer translations of the same underlying job-role architecture.

## Core Architectural Correction

CareBloomOS is not the base or default form of the system.

It is the first mature expression profile developed for a more fundamental set of functions.

Do not reason like this:

```text
CareBloom role
    -> translated into
Pokemon role
    -> translated into
Magical role
```

Reason like this:

```text
Functional kernel / archetype
            ->
    Expression profile
      /     |      \
 CareBloom Pokemon Magical Zodiac ...
```

No expression profile is ontologically primary.

CareBloom has historical precedence because it was developed first, but not architectural precedence.

## System Levels

```text
Expression profiles
  Adapt to any world

Functional kernels
  Shared by all profiles

Journey / Mini ARK
  Configuration engine; sets, combines, adapts

HEXSEED
  Persistent platform / body; identity, memory, continuity
```

HEXSEED remains HEXSEED regardless of the expression currently being worn.

Journey / Mini ARK is responsible for moving HEXSEED between valid configurations. It may identify the desired operating context, select an expression profile, gather required assets and configuration, translate persistent functions into profile-specific language, activate required tools and interfaces, verify the resulting state, and preserve continuity across the transition.

Journey is not itself the configuration.

## The Seven Functional Kernels

These are the common denominator beneath all expressions.

The names below are neutral system vocabulary, not CareBloom lore.

| Kernel | Job Role | Basic Archetype | Core Responsibility | Primary Verbs |
| --- | --- | --- | --- | --- |
| INTEGRATE | Systems Integrator / Orchestrator | Steward, Coordinator, Generalist | Hold the whole system together and coordinate specialized roles | integrate, coordinate, balance, synthesize, orchestrate |
| SUSTAIN | Continuity / Recovery Specialist | Healer, Custodian, Caregiver | Preserve wellbeing, continuity, recovery, and what should survive change | heal, sustain, stabilize, preserve, restore |
| PERCEIVE | Diagnostics / Intelligence Specialist | Seer, Scout, Analyst, Guardian | Detect hidden conditions, diagnose problems, anticipate risk, protect through awareness | inspect, diagnose, detect, ward, anticipate |
| MAINTAIN | Maintenance / Construction Specialist | Builder, Gardener, Craftsperson | Repair, grow, provision, clean, construct, and maintain resources | build, repair, grow, clean, provision |
| REGULATE | Environmental / Context Specialist | Weatherworker, Mediator, Atmosphere Keeper | Shape environmental conditions so the system can operate effectively | regulate, adapt, ventilate, moderate, condition |
| ROUTE | Access / Movement Specialist | Pathfinder, Courier, Navigator | Get people, information, resources, or processes where they need to go | route, retrieve, connect, deliver, traverse |
| SYNCHRONIZE | Resonance / Timing Specialist | Bard, Conductor, Amplifier | Coordinate rhythm, signal, communication, tempo, and collective action | synchronize, amplify, harmonize, signal, modulate |

These are functional kernels, not characters, costumes, colors, elements, fandom references, or UI skins.

They should survive every translation intact.

## Expression Profiles

An expression profile answers:

```text
How does this worldview understand these jobs?
```

Each profile may translate a kernel into a new name, symbolic object, element, character, archetype, icon, color palette, UI language, workflow vocabulary, animation or state treatment, sound language, and asset family.

The role underneath remains stable.

Example:

```text
Kernel: SUSTAIN

CareBloom expression:
Heartstone
visible care / restoration / continuation

Pokemon expression:
Everstone
hold / sustain / preserve continuity through transition

Magical expression:
restorative ward, heart crest, preservation spell, or equivalent
```

The SUSTAIN kernel is authoritative.

Heartstone and Everstone are peer translations of it.

## Semantic Translation

Translation should be semantic, not merely cosmetic.

Do not ask only:

```text
What is the same color?
```

Ask:

```text
What symbol in this expressive system performs, represents, or evokes the same job?
```

Direct translations are valid:

```text
PERCEIVE -> Moonstone -> Moon Stone
```

Conceptual translations are also valid:

```text
SUSTAIN -> Heartstone -> Everstone
```

The names are visually unrelated, but the functional correspondence is stronger: maintain this state, preserve continuity, and avoid discarding what matters during transition.

## Expression Profile Biases

Each profile should have a declared specialty or interpretive bias, but specialties remain editable.

| Expression | Possible Specialty |
| --- | --- |
| CareBloom | care, continuity, relational infrastructure, stewardship |
| Pokemon | acquisition, capture, collection, categorization, development |
| Magical | transformation, activation, capability, power, becoming |
| Zodiac | archetypal synthesis, patterns, correspondence, interpretation |
| Power Rangers | team configuration, heroic specialization, coordinated action |

These specialties explain why Journey might choose one expression over another.

Examples:

- Need to acquire, classify, and preserve a large asset set? Pokemon expression may be useful.
- Need to transform files, resources, or processes from one state into another? Magical expression may be useful.
- Need continuity, maintenance, recovery, or relational context? CareBloom expression may be useful.
- Need recurring patterns or synthesis across signals? Zodiac expression may be useful.
- Need coordinated specialization across several active capabilities? Power Rangers expression may be useful.

This makes manifestations operational perspectives, not cosmetic themes.

## Profile-Neutral Build Formula

Use:

```text
Functional kernel
      +
Expression profile
      +
Profile-specific translation
      +
Operational vocabulary
      +
Visual / audio / UI assets
      =
Active HEXSEED configuration
```

Do not use:

```text
Carestone
      +
reskin
      =
other mode
```

## Source-Of-Truth Hierarchy

For implementation and synthesis, reason in this order:

```text
1. What job needs to happen?
2. Which functional kernel owns that job?
3. Which expression profile is currently active or best suited?
4. How does that profile translate the kernel?
5. Which assets, terminology, interfaces, and behaviors implement it?
```

This prevents expressive vocabulary from contaminating underlying architecture.

Metadata should be able to say:

```text
KERNEL: SUSTAIN
PROFILE: POKEMON
EXPRESSION: EVERSTONE
FUNCTION: CONTINUITY_MAINTENANCE
```

It should not require this to understand the underlying role:

```text
CARESTONE: HEARTSTONE
```

CareBloom-specific metadata may still be included when CareBloom is active, but it is no longer required to describe the underlying role.

## Design Principle

Do not confuse the first language developed with the language of reality.

CareBloom revealed the role system.

It does not own it.

Pokemon, Magical, Zodiac, Power Rangers, and future manifestations should be allowed to become equally complete interpretations of the same functional architecture.

The intended relationship:

```text
same jobs
different metaphors
different strengths
different expressive languages
one continuous HEXSEED
```
