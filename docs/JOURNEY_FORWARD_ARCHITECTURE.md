# Journey: Forward Architecture

Governance direction dated 2026-09-29, not a claim of completed implementation.
See JOURNEY_PUBLIC_CHECKPOINT.md for the current verified boundary.

## Identity and purpose

Journey is a local HEXSEED companion for continuity, stewardship, coordination
and reduced user-computer friction. It is intended to coordinate among Project
ARK systems: eventual PMM/PWM, Financial ARK, Entrepreneurial ARK and other domain
ARKs. Project ARK is the continuity-bearing umbrella, not another name for Journey.
Mini ARK remains the implementation/repository name.

Active Project ARK continuity belongs on C: and is intended to migrate together
between HEXSpressions. No deeper root is specified. R: holds durable resources,
projects, media, libraries, records and source material. This filesystem law
does not authorize automatic migration or classify existing material by name.

## Graduated agency

| Dimension | Meaning |
|---|---|
| Capability | What Journey technically knows how to do |
| Authorized ceiling | Highest authority Junior has permitted |
| Active authority | Authority exercised for the present operation |
| Observation scope | Information/surfaces currently authorized for observation |

Capability is not authority; authorization is not active use; active use is not
permanent. Intended behavior rests at minimum authority, escalates proportionally
to demonstrated need within the ceiling, verifies/receipts work and contracts
when the need ends. Junior's explicit ceiling reduction persists until Junior
changes it. Whole-system automatic escalation/contraction is not implemented.
Read authority is separate from mutation authority and from action/risk classes.

## Gate A: Perception / Observation

Bounded observation across authorized HEXSEED surfaces, not defined by one
implementation such as filesystem scanning or runtime telemetry. Planned depths:

| Depth | Surfaces |
|---|---|
| A.1 Structural | Existence, paths, structure, metadata, process/program presence and basic relationships |
| A.2 Operational | Legitimate read-only runtime interfaces, process/service state, events, logs, resources and authorized I/O/state reports |
| A.3 Repository/state | Structured stores, configuration repositories, databases, indexes, manifests, catalogs, meaningful caches, histories, registries and accumulated application/system knowledge |
| A.4 Cross-surface synthesis | Correlate authorized filesystem, runtime, repository, application and system evidence across surfaces/time |

These are observation depths within A, not new gates or permission grants.
Preserve provenance, evidence strength, confidence and UNKNOWN. Weak evidence
does not silently become fact. Bounded inference/classification belongs in A.
Credentials, secrets, clipboard, private messages, browser content, process memory,
network payloads and user-entered text require appropriate explicit scope/authority.

## Gate B: Action / Hands

Bounded, deterministic external-state changes under established governance:
evidence-qualified, dependency-aware, reversible where required, verified and
receipted at minimum authority. Evidence authorizes one exact operation, not
unrelated actions. The current move-evidence integration is fixture-verified;
it has no production issuer and does not enable live managed moves.
Identity confidence is not action confidence. A search finding no references
is not dependency clearance. Undo protects current reality, including new occupants.

## Gate C: Advanced Judgment / Proposal

Planned reasoning beyond established procedures: novel situations, alternatives,
consequential proposals, potential governance/procedure changes and genuine human
judgment. C is not all inference; A already requires bounded interpretation.

## Gate D: Development / Capability Expansion

Evolving direction, not a completed gate. Recognize missing capabilities,
investigate solutions, construct/test candidates in isolation and propose adoption.
Self-healing/self-diagnosis is not self-authorization; withheld authority stays withheld.

Earlier planning used D for destructive operations. That history is not erased:
here D means development/expansion, while destructive/high-impact operations remain
separately governed action/risk classes with applicable explicit approval. No
automatic gate-to-risk mapping exists. Earlier release vocabulary also used
A=Shadow, B=Bounded Stewardship, C=Sustained Stewardship, then Journey Soft Launch.
Those historical labels remain in code/configuration and older documents. This
forward doctrine does not change runtime policy, ceilings or graduation status.

## Reasoning boundary and the new map

Journey has increasingly strong deterministic machinery and grounded contracts
for objectives, evidence, capabilities, authority and success/failure/UNKNOWN.
It does not independently perform all open-ended reasoning about evidence or
invent the next conceptual route. Near-term agency: I know -> I can -> I may -> I do.

Journey does not need to know every terrain. It needs to know when it needs a new
map. Distinguish insufficient evidence, capability, authority and reasoning and
route each appropriately. Resource feasibility is independent: technically
preferred does not mean affordable or available. Never silently trade safety
for affordability; RESOURCE_BLOCKED is a valid outcome.

## Planned reasoning council

Future only: approximately three heterogeneous independent LLM reasoners, all
examining the problem; the third is not merely a tiebreaker. Outputs are advice
and evidence, not votes that create truth or authority. For disagreements,
including 1-1-1, Journey need not infer a common root beyond its capability.
Relay findings back for common requirements, conflicting assumptions,
discriminating evidence and minimum useful next observations.

Then ask: can I obtain that evidence using capabilities and authority I possess?
If yes, gather and return it; otherwise name the boundary accurately. Potential
route: Journey -> Council -> local evidence -> Council -> specialist assistance
(Codex/ChatGPT) -> Junior when governance/authorization genuinely requires Junior.
Council advice never grants authority.

Privacy remains binding. Free/available remote models do not receive HEXSEED
information by default. Local and remote models have different implications.
Future consultation packets must be minimum-necessary, provenance-preserving
and explicitly governed. No providers or transmissions are enabled by this plan.

## Present objective

ARK and future work without constant filesystem cognitive overhead. CareBloom
comes first: identify ownership -> establish custody -> preserve provenance ->
refine classification later. Perfect classification is not required before safe
custody. LEAVE protects individually blocked material, not a desired endpoint
when safe stewardship is possible. Holds must not block unrelated eligible work.
Implement new infrastructure only for observed needs, not because this roadmap
exists. Junior governs; Journey tends.
